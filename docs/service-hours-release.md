# 서비스 제공시간 변경 (#176)

## 구현 범위

- 서비스 제공시간: 매일 07:00~19:00 · 주말·공휴일 포함.
- `lib/service-hours.ts`의 공통 값으로 메인·서비스 소개·푸터·예약 안내와 30분 간격 예약 옵션을 생성한다.
- 고객센터 상담시간은 기존 06:00~18:00을 유지하며 푸터에서 별도 라벨로 구분한다.
- 예약 폼과 서버 스키마가 범위 밖·30분 간격 밖·잘못된 형식의 도착/진료 시간을 거절한다. 신규 회원 예약의 직접 REST INSERT도 DB 트리거로 같은 범위를 검사한다.
- 기존 예약 UPDATE와 서버의 기존 데이터 처리·테스트 시드는 시간 변경으로 소급 차단하지 않는다.
- 주말·공휴일 30% 할증 및 최소 청구·연장 계산은 기존 요금 로직을 사용한다.

## 자동 종료

마이그레이션 `20260708000064_service_hours.sql`은 기존 자동 종료 RPC의 KST 당일 상한을 18시에서 19시로 변경한다.

자동 종료 시점은 `max(예정 종료, min(예정 종료 + 3시간, KST 당일 19시))`이다. 기존 예약의 예정 종료가 19시 이후이면 예정 종료 전에는 닫지 않는다. `ended_at`은 배치 실행 시각 대신 예정 종료시각을 기록하여 추정 연장 청구를 방지한다.

## 리뷰에서 결정할 항목

사용자가 예상 종료시각을 19시 이내로 제한하기로 확정했다. 최소 예약 2시간이면 마지막 시작은 17시이며 2시간 30분은 16시 30분, 4시간은 15시까지 시작할 수 있다. 화면 선택·폼·서버·신규 회원 DB 입력에 같은 제한을 적용한다.

이 제한은 예약 당시 예상 종료 검증이다. 기존 예약과 실제 현장 지연·연장 처리는 소급 차단하거나 19시에 강제 종료하지 않는다.

## 약관 및 배포 순서

- 노션 원문 제13조 ③④의 문구를 그대로 반영했다. 동의 이력을 구분하도록 버전·개정일을 2026-10-04로 올리고 기존 본문 해시를 보존했다.
- 사용자가 날짜는 Notion 자료대로 유지하도록 확정했다. 원문 시행일은 2026년 9월 3일이며 별도의 공고일 날짜는 표기돼 있지 않아 임의로 생성하지 않는다. 개정일/동의 버전은 공고일과 구분한다.
- 스테이징 DB에 마이그레이션 64를 먼저 적용한 뒤 새 화면을 확인한다. 다른 PR의 61~63 적용 이력과 순서를 확인한다.
- DB 크론 스케줄은 변경하지 않았다. 운영 적용 뒤 자동 종료 배치의 최근 실행 성공 여부를 확인한다.
- 이 PR에서 원격 DB 적용, main 병합 및 운영 배포를 실행하지 않는다.
