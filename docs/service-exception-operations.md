# 예외 종료 운영 처리 (#185 / #203)

사용자 확정 방침과 이용약관 제11조④·제16조⑦·제18조③에 따라 처리한다.
운영 판정 담당자는 김서현이며, 시스템 권한은 개인 전체/정산 계정과 MFA가 필요하다.
고정된 예외 요금표나 최소 1시간 요금을 자동 적용하지 않는다.

## 순서

1. 파트너가 회사·파트너 사유 또는 응급 중단으로 종료한다. 시작 전 제공 불가는
   관리자 > 예외 종료 운영 확인에서 예약번호·사유·비공개 증빙 참조로 등록한다.
2. 실제 제공 내용과 시간을 확인하고 최종 **현금** 청구액, 파트너 지급액,
   사유, 증빙 문서명/관리번호를 기록한다. 의료 상세 내용은 사유에 입력하지 않는다.
   할인·사용 포인트를 제외한 현금 금액을 입력한다. 제공 불가는 현금 청구액 0원이다.
3. 주문별 지정 환불액을 NICEPAY 관리자에서 처리한다. 이 기능은 취소 API를 호출하지 않는다.
   결과가 불명확하면 재환불하지 말고 원거래 잔액을 확인한다.
   추가 청구가 있으면 3일 유효 결제 링크가 고객 인앱 알림으로 발급된다.
4. `PG 결과 조회 · 원장 기록 · 보류 해제`로 모든 주문의 주문번호·거래번호·승인액·잔액·상태를
   서버에서 조회한다. 추가결제 미완료, 잔액 불일치, PG 조회 실패는 보류를 유지한다.
   현금 0원인 PAID 원장은 PG 거래 없이 확인하며 제공 불가 시 실제 사용 포인트를 복원한다.
5. 검증된 현금 환불 원장, 최종 분배, 단일 정산, 서비스 완료, 고객 알림과 감사 기록을
   한 DB 트랜잭션에서 기록한다. 이미 최종 지급액으로 만든 정산에서 환불액을 다시 차감하지 않는다.
   승인 총액·할인은 보존하며 분배 변경 전 값도 별도로 기록한다.
6. 제공 불가의 사용 이벤트는 증빙 확인과 전액 현금 환불 후 복원한다.
   고객 취소·노쇼·응급 중단의 혜택은 이 경로로 복원하지 않는다.
   복원 대기 예외가 있는 행사는 종료할 수 없다. 실제 할인 활성화는 별도다.
7. 정산은 PENDING으로 생성된다. 지급은 기존 승인/담당자 분리/이체 절차를 따른다.

## 제한과 복구

- 판정은 한 번 기록하며 직접 수정하지 않는다. 입력 전 두 금액과 증빙을 검토한다.
  잘못된 판정은 PG 재처리 없이 운영 사고로 등록하고 별도 원장 대조·보정 검토를 한다.
- 기존 환불 요청, 환불 원장, 정산, 미결제 거래가 있는 건은 단순 판정을 거절한다.
  기존 거래 처리 상태를 확인하고 별도로 대조해야 한다. 처리 중 금액을 덮어쓰지 않는다.
- 지급액이 고객 현금 청구액보다 크면 차액은 회사 부담(음수 수수료)으로 표시된다.
  회사 부담이 있는 판정도 근거와 지급액을 확인한 뒤 별도 정산 승인을 거친다.
- 금액 입력 상한 1천만원과 거래 수 상한(기존 20건)은 입력 오류·비정상 건을 막는 기술 제한이다.
  해당 범위를 넘는 건은 자동 처리하지 않고 개별 대조한다.
- DB 기록 실패 시 전체 DB 변경은 롤백한다. PG 결과 조회를 다시 할 수 있지만 앱은 환불을 재실행하지 않는다.
- 고객 상세 화면은 예외 건의 현금 금액·처리 상태만 보여 준다. 증빙과 파트너 지급액은 반환하지 않는다.

## 배포·확인

- PR #203의 마이그레이션 **78 → 82**가 필요하다. 79~81은 다른 PR의 이력이므로
  환경별 전체 마이그레이션 순서를 확인하고 원격 적용 범위를 별도 승인받는다.
- 이 PR 작업에서 원격 DB 적용, 실제 PG 거래, 이벤트 활성화, main 병합은 수행하지 않는다.
- SQL: 4시간 Basic 제공 불가, Basic/Plus 주말·공휴일 할증 부분 제공/응급,
  추가결제 대기, 0원 현금·포인트, 권한·MFA·증빙·중복·알림 실패 롤백·감사 기록을 검사한다.
- PG 모의 조회: 주문·거래·금액·잔액·상태 불일치와 조회 실패를 검사하며 취소·승인 호출이 없음을 확인한다.
- 원격 적용 후 담당자 로그인으로 화면과 PG 테스트 거래의 결과 대조를 확인해야 한다.
