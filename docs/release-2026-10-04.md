## 병합·운영 배포 전 확인

- [ ] 이 PR의 통합 CI(빌드 및 실제 로컬 DB 마이그레이션·권한 검사)가 모두 통과했는지 확인한다.
- [ ] 대상 운영 DB의 적용 이력을 확인한다. #177의 61·62·67·68이 이미 적용된 경우 기존 파일을 수정하거나 재적용하지 않는다.
- [ ] 새 마이그레이션 **63·64·65·66·69·70·71**을 대상 확인 후 적용한다. 기존 운영 이력 사이에 63~66을 추가해야 하므로 dry-run에서 누락 버전과 순서를 확인하고 CLI의 과거 버전 포함 적용 절차를 사용한다. 70은 노쇼 원장·공개 보정, 71은 실제 이용자 후기 공개 동의·3년 만료·철회·검토 전 공개 차단이다. 원격 DB 적용은 별도 승인 후 수행한다.
- [ ] 운영 DB 적용은 운영 배포보다 먼저 완료한다. 신규 상세/후기/이벤트 테이블·RPC가 없으면 새 화면 요청이 실패할 수 있다.
- [ ] 파트너 상세의 `partner_public_release.enabled=false`를 확인한다. 고지 정본은 미정이므로 공개하지 않는다. 확정된 항목·목적·대상·기간·철회 안내 및 동의 버전을 별도 검토한 후 후속 PR로 공개 승인한다. 기존 동의 철회는 차단하지 않는다.
- [ ] 71 적용 후 동의 증빙 미확인 제공 후기 12건과 미검토 사이트 후기가 공개되지 않는지 확인한다. `review_publication_release.health_enabled=false`를 유지한다. 작성자의 동의와 실제 이용자의 민감정보 공개 동의를 동일하게 취급하지 않는다. 절차·정본·증빙 보관/파기 준비는 docs/review-publication-consent.md에 따른다.
- [ ] 서비스 시간·예약 종료 제한·FAQ·후기·대표 이미지를 운영 도메인에서 확인한다. 약관 날짜는 Notion 정본 기준이며 별도 공고일을 임의로 생성하지 않는다.
