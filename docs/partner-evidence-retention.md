# 증빙 원본 30일 보유 (#199)

## 결정과 적용

- 사용자 결정 2026-10-05: 최초 심사 결과 통지 후 30일을 이의신청 기간으로 한다.
- 심사 중에는 원본을 보유하고, 최초 결과 알림과 같은 트랜잭션에서 기한을 기록한다. 재심사로 기한을 연장하지 않는다.
- 본인 이의신청 또는 심사 담당자의 접수는 파기를 보류한다. 기간 내 신청만 허용한다. 담당자+MFA가 처리 종료하면 원래 30일 기한 경과 여부에 따라 파기를 재개한다.
- 인증 메타정보와 인증 상태는 활동 중 유지하며, 원본·파일명·크기를 제거한다. 감사/운영 기록의 별도 보유기간을 이 PR에서 임의 확대하지 않는다.
- 만료 시 원본 접근을 DB/Storage 정책에서 차단하고 기존 cron에서 Storage API 삭제를 재시도한다. 원본 삭제 성공 후 대기 큐를 제거한다. 연결하지 못한 신규 파일의 하루 후 파기도 유지한다.
- 서명 링크는 최대 5분이며 보유기한까지 남은 시간으로 제한한다.

## 기존 자료와 운영 절차

- 실제 심사 감사 기록이 있는 기존 자료만 그 시각으로 연결한다. 이미 30일이 지났으면 적용 후 파기 대상이 될 수 있으므로 기존 이의신청이 있으면 적용 전 확인한다.
- 결과 통지일이 없는 자료는 날짜를 추정하지 않는다. 관리자 목록의 보유기간 상태 확인에서 사유/기존 최종 결과를 입력하고 재통지한다. 이후 실제 재통지일부터 30일을 계산한다.
- 파트너는 My 프로필에서 항목별 기간과 상태를 조회하고 이의신청한다. 관리자는 같은 항목에서 접수/종료 사유를 남긴다.
- 새 증빙 업로드 플래그는 아직 false 유지한다. /partner-evidence-notice 및 /privacy 연결 고지는 준비하지만 읽기 전용 노션 정본 반영과 수집 활성화는 별도 확인 대상이다.
- 마이그레이션 85를 화면 배포 전에 적용한다. 이 PR은 원격 DB에 자동 적용하지 않는다.

## 검증

- SQL: 통지 성공/실패·30일 경계·재심사 미연장·타인/직접 수정/MFA 차단·다중 원본 파기·진행 중 이의신청 보존·처리 종료 뒤 파기·재시도·검증 정보 보존·기존 자료 재통지.
- 순수 검사: 서명 URL의 만료/보류/잘못된 날짜/조회 실패/남은 기한 제한.
