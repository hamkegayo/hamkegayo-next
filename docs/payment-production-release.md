# 운영 결제 릴리즈

## 현재 확인한 것

- 결제 어댑터는 운영 Client Key를 받으면 `https://api.nicepay.co.kr`로 연결한다.
- 결제창은 카드 결제를 호출한다. 추가 결제수단·빌링키 도입은 별도 작업이다.
- 로컬 `.env.local` 운영키로 조회 인증을 확인했다: HTTP 404 / U107(거래 없음).
  무작위의 존재하지 않는 주문번호를 GET 조회했으며 승인·취소는 호출하지 않았다.
- Vercel의 운영 Client Key가 로컬 값과 일치함을 확인하고 Secret Key를 갱신했다.
  기존 PG 변수는 Production과 Preview가 함께 사용하는 항목이어서 Secret 갱신도
  두 환경에 적용됐다. 실제 적용은 다음 배포부터이며 현재 운영 배포를 실행하지 않았다.
  Secret은 저장 후 읽을 수 없으므로 기존 값의 누락 여부나 값 일치를 다운로드로 판정하지 않는다.
- 이 결과는 키의 조회 인증 확인이다. 실제 카드 승인·부분취소·예약 상태 전이는 배포 후 검증한다.
- 키 값과 조회 응답 원문은 저장소·PR·로그에 남기지 않는다.

## 병합 전 운영 환경 확인

로컬 `.env.local`은 Vercel에 업로드되지 않는다. Production에 아래 값을 등록한 후
릴리즈 PR을 병합하고 새 배포에서 적용 여부를 확인한다. 로컬 환경 파일 전체를 복사하지 않는다.

| 환경변수                                                    | 용도                                                   |
| ----------------------------------------------------------- | ------------------------------------------------------ |
| `NEXT_PUBLIC_NICEPAY_CLIENT_KEY`                            | 운영 결제창 Client Key. 빌드 시 적용되므로 재배포 필요 |
| `NICEPAY_SECRET_KEY`                                        | 서버 승인·조회·취소 인증. 공개 변수로 등록하지 않음    |
| `NEXT_PUBLIC_SITE_URL`                                      | `https://www.hamkegayo.kr`, 안내 메일의 링크 주소      |
| `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` | 운영 Supabase 프로젝트                                 |
| `SUPABASE_SERVICE_ROLE_KEY`                                 | 위 운영 프로젝트에 대응하는 서버 키                    |
| `RESEND_API_KEY`, `EMAIL_FROM`, `PAYMENT_ALERT_EMAIL`       | 고객 안내 및 결제 사고 알림                            |
| `CRON_SECRET`                                               | 운영 배치 인증                                         |

- [ ] Production 키가 로컬에서 확인한 운영 가맹점의 키와 일치한다.
- [ ] Preview도 현재 운영키를 공유한다. 일반 개발 테스트용 Preview는 결제 전 Client/Secret을
      테스트키 한 쌍으로 분리한다. 운영키로 화면 검증할 때는 실제 거래 환경임을 구분한다.
- [ ] 운영 Supabase 연결과 미적용 마이그레이션을 확인한다.
      이 릴리즈에는 개발 브랜치의 관리자·정산·보유기간 파기·소셜 가입 마이그레이션
      `20260708000048`~`20260708000060`이 포함된다. 이미 적용된 항목을 재작성하지 않는다.
- [ ] DB 마이그레이션을 앱 배포보다 먼저 적용한다.
- [ ] 관리자 MFA/duty는 `admin-account-release-checklist.md`에 따라 확인한다.
- [ ] 배치 `expiry-sweep`, 보유기간 파기 및 Vercel keepalive/reminders의 실제 실행을 확인한다.
- [ ] CI와 Vercel Preview 검증을 완료한 뒤 사용자가 main 릴리즈 PR을 병합한다.

## 배포 후 실제 거래 검증

테스트 담당자가 결제창에서 직접 카드 결제한다. 운영 DB에 개발용 seed/통합 테스트를 실행하지 않는다.
특히 `test:nicepay`는 샌드박스 전용이며 운영키 조회 확인에는 아래 명령을 사용한다.

```powershell
npm.cmd run check:nicepay-live
```

- [ ] 운영 로그인 → 예약 → 파트너 수락 → 선택 → 카드 결제 → 예약 확정.
- [ ] PG 거래와 `payments` PAID, 예약 CONFIRMED, 정산 원장 금액을 대조한다.
- [ ] 정상 취소 경로로 전액 취소하고 PG 잔액·DB 상태·환불액을 대조한다.
- [ ] 부분취소 및 추가결제에서 원거래·추가 거래·정산 금액을 대조한다.
- [ ] 결제창 취소·실패·재진입으로 이중 청구가 발생하지 않는다.
- [ ] 승인 불확정/보상 취소 실패는 재승인하지 않고 결제 사고 목록과 알림으로 추적한다.
- [ ] PG 관리자에서 직접 취소한 건은 DB에 자동 반영됐다고 간주하지 않는다.
      외부 조치 완료 후 관리자 사고 처리 메모를 남기고 상태 정합성을 확인한다.
- [ ] 테스트 거래 정리와 결과를 #81에 기록한 뒤 운영 검증 완료로 처리한다.

## 릴리즈 범위와 후속 작업

이 릴리즈는 현재 dev에 병합된 관리자 기능, 파트너 기본정보, 보유기간 파기 확장,
카카오 소셜 가입, 네이버 로그인 점검 중 표시 및 기존 UI/예약 보완을 포함한다.
main에만 있던 이전 릴리즈 병합 이력도 릴리즈 브랜치에 통합했다.

사진 교체 #174, 실제 후기 #175, 파트너 상세 #173, 이벤트 #159,
서비스 시간/약관 동기화 #176은 후속 PR로 진행한다.
빌링 #123 및 계좌 실명조회 #100은 일반 카드 결제와 별도 기능이다.
