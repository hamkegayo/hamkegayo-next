# 파트너 자격·경력 증빙 관리 (#199)

## 배포 및 활성화

- 마이그레이션 77을 프런트엔드보다 먼저 적용한다. 원격 적용은 별도 승인 대상이다.
- 이름은 실제 기본정보로 표시한다. 파트너 생년월일 저장 경로가 없어 새로 수집하지 않고 `등록된 정보 없음`을 표시한다.
- 기존 자격·경력 및 인증 상태는 보존한다. 기존 별도 제출 증빙은 담당자가 확인하며 일괄 재제출을 요구하지 않는다.
- 새 여러 파일 등록은 `partner_evidence_release.enabled=false`로 배포한다. 최신 개인정보처리방침의 증빙 수집 항목·목적·보유기간·파기 안내 확인 후 활성화 범위를 별도로 승인한다. 커넥터가 반환한 9월 10일 스냅샷은 최신 개정 증거로 사용하지 않는다.
- 고객 상세 공개 플래그 및 동의는 별도이다. 새 등록 플래그가 고객 정보 공개를 활성화하지 않는다.

## 파트너 절차

1. `/partner/profile` 하단에서 자격, 의료기관 근무 경력, 병원동행 경력을 선택한다.
2. 해당 유형의 필수 정보와 기간·현재 재직 여부를 입력한다.
3. JPG·PNG·PDF를 최대 5개, 파일당 최대 5MB로 첨부한다. 주민등록번호 뒷자리·주소를 가리고 환자·이용자 정보를 제출하지 않는다.
4. 파일은 본인 세션으로 비공개 Storage에 업로드하고 서버가 실제 내용의 형식·크기를 검증한 뒤 원자적으로 등록한다. 등록 중단 후 연결되지 않은 파일은 하루 뒤 파기 대상이 된다.
5. 심사 대기/인증 완료 상태를 확인한다. 등록 자료의 `증빙 확인`은 본인의 비공개 파일 링크만 발급한다. 기존 수정 절차는 담당자 문의 또는 삭제 후 신규 등록·심사다.

## 관리자 절차

- 김서현 담당자가 개인 전용 심사/전체 관리자 계정으로 MFA 인증 후 `/admin/qualifications`에서 확인한다.
- 경력은 `?kind=work` 목록에 의료기관/동행 유형을 구분한다.
- 증빙 열람 사유 5~500자를 입력한다. 해당 자료 열람 감사 기록을 남긴 뒤 해당 파일만 5분 유효 링크를 발급한다.
- 관리자 검증 전에는 인증 완료로 표시하지 않는다. 심사 결과 및 사유는 기존 알림 경로로 전달한다.

## 삭제와 중단 처리

- 자료 삭제·파트너 계정 삭제 시 새 증빙 메타데이터는 cascade로 삭제되고 경로는 파기 대기 목록으로 이동한다.
- 기존 keepalive cron은 Storage API 삭제 성공 후 대기 목록을 지운다. 실패하면 목록을 남겨 재시도한다.
- 등록 응답을 받지 못한 경우 저장 여부를 확인할 때까지 파일을 즉시 삭제하지 않는다. 원장에 연결된 파일은 중단 파일 파기에서 제외한다.
