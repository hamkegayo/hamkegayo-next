# 실제 할인 활성화 (#185)

## 사용자 결정

- 2026-10-05 실제 할인 활성화 승인, 직원/테스트 제외 계정 **추가 없음**. 기존 제외 기록은 유지한다.
- #81 운영 검증 완료는 사용자 확인이며 에이전트가 실거래를 새로 실행하지 않았다.
- 기존 정책(인증 이메일 1회, 신규 이용자, 20명, 기본 1시간만 무료, 최소 2시간, 포인트 중복 금지)을 유지한다.

## 배포 순서

1. 환경별 서로 다른 서버 `OPENING_EVENT_EMAIL_HMAC_KEY`를 Secret으로 등록한다. 키 원문은 출력/커밋하지 않는다. 행사 중 교체 금지.
2. 주말 0% PR #210 및 이 PR의 공개 고지를 먼저 배포한다. /privacy에서 /event/opening 안내를 연결한다. 읽기 전용 노션 정본에도 담당자가 반영한다.
3. 운영 배포에 새 키가 포함됐는지 확인한 뒤 마이그레이션 84를 적용한다. Vercel 변수 등록만으로 기존 배포의 환경은 바뀌지 않는다.
4. 적용 이후 신규 적격 예약의 결제 준비에서 실제 할인과 정원 확보가 작동한다. 진행 중 기존 결제·정원·제외 목록은 초기화하지 않는다.
5. 행사 종료 행에는 활성화 마이그레이션이 실패한다. 공개 플래그만 켜고 키 설정을 생략하지 않는다.

## 검증

- 이메일 정규화/HMAC 키 분리/길이 검사, SQL 할인·정산·환불·예외·권한·정원 및 23건 동시 확보 검사는 기존 CI로 유지한다.
- Preview 결제 운영키는 연결하지 않는다. HMAC 설정이 실제 청구 허용을 의미하지 않는다.
- 이 PR 작성만으로 원격 플래그와 기존 배포는 변경되지 않는다. 병합/배포는 사용자 수행.
