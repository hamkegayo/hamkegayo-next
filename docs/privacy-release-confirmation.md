# 운영 개인정보 고지 확인 — PR #177

이 문서는 코드·설정에서 확인한 사실과 정본 개정에 필요한 확인 사항이다. 공개 개인정보처리방침을 대신하지 않으며, 미확정 계약 내용은 확정 문구로 취급하지 않는다.

## 카카오 로그인 확인 결과 (2026-10-04)

- 로그인 버튼은 Supabase의 `kakao` 제공자를 호출한다. 애플리케이션에서 추가 scope를 지정하지 않는다. 최종 제공 범위는 카카오 앱의 동의 항목과 Supabase 제공자 설정에 달려 있다.
- 스테이징의 실제 카카오 identity에서 **필드명만** 확인했다. 개인별 값은 조회·기록하지 않았다.
- 확인된 필드: `provider_id`, `sub`, `iss`, `email`, `email_verified`, `phone_verified`, `avatar_url`, `name`, `full_name`, `preferred_username`, `user_name`.
- 카카오 계정 식별자·이메일 및 확인 상태·프로필명/닉네임·프로필 이미지 주소가 인증 저장소에 남을 수 있다. `full_name`이라는 키 이름만으로 법적 성명 수집을 단정하지 않는다.
- 추가 가입 화면은 이메일을 소셜 계정에서 확인하고, 이름·휴대전화번호·약관 동의를 별도로 받는다. `phone_verified` 상태가 있는 사실을 휴대전화번호를 카카오에서 제공받는 것으로 해석하지 않는다.

### 정본 개정 시 반영할 내용

- 제공자: 카카오. 인증 처리 인프라: Supabase.
- 수집 항목: 외부 소셜 제공자 정보·계정 식별자, 이메일과 확인 상태, 제공되는 프로필명/닉네임·이미지 주소 및 인증 관련 상태. 실제 운영 카카오 동의 항목과 대조한 뒤 최종 확정한다.
- 목적: 회원 식별, 소셜 로그인·인증 및 회원 가입 연결. 프로필명·이미지를 별도로 활용한다면 그 목적도 확인한다.
- 가입자가 직접 입력하는 이름·휴대전화번호와 소셜 제공 항목을 구분한다.
- 보유기간, 선택/필수 구분, 동의 철회 경로와 소셜 연결 해제 후 보유 처리도 정본 담당자가 확정한다.

## NICEPAY 코드 확인 결과

- 브라우저 결제창: 결제수단(card), 주문번호, 결제금액, 상품명, 인증 결과 반환 URL을 전달한다. 상품명에는 예약 코드가 포함된다.
- 서버: PG 거래 식별자·인증정보, 결제금액·주문번호를 이용해 승인·조회·취소·부분취소를 처리한다. 취소 사유 및 부분취소 금액을 전달한다.
- 고객의 카드번호 전체를 애플리케이션 DB에 저장하는 코드는 이 경로에서 확인하지 못했다. PG 결제창에서 PG가 직접 수집하는 전체 항목은 코드만으로 확정할 수 없다.

### 계약에서 제공받아야 하는 내용

1. 실제 계약 상대방의 수탁 법인명 (상호 표기만으로 추정하지 않음).
2. PG가 직접 수집하는 결제정보와 회사가 전달하는 정보의 구분 및 처리 업무.
3. 국외 처리·이전 및 재위탁 여부. 해당된다면 국가·수탁자·이전 항목·시기/방법·목적/보유기간·거부 방법.
4. 계약상 정보 보유·파기 조건 및 문의 담당자.

## 정본과 공개 코드 반영 절차

1. 카카오 동의 화면/제공자 설정 및 NICEPAY 계약 내용을 정본 담당자가 확인한다.
2. Notion 정본에 확정 내용과 공고일·시행일을 반영한다. 현재 `legal-check`는 Notion 읽기 전용이며 정본을 자동으로 쓰지 않는다.
3. 최신 정본을 다시 받아 `lib/legal/privacy.ts`에 동기화한다. 버전·개정일·본문 해시를 갱신하고 기존 동의 이력을 보존한다.
4. 재동의·개정 안내 필요 여부와 시행 시점을 확인하고 `test:legal` 및 동의 검증을 실행한다.
5. 계약·시행일 미확정 상태에서 공개 고지가 완료됐다고 표시하거나 운영 릴리즈를 병합하지 않는다.

받은 Notion 스냅샷 시각과 마지막 수정 시각이 일치하지 않아 최신 개정분의 반영 여부는 확정하지 않았다. 이 문서에는 원문 사본을 저장하지 않는다.
