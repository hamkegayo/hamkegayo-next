# 이벤트 팝업 예약 CTA

- 주 버튼은 `예약하기`, 보조 버튼은 기존 `카카오톡 상담하기`다. 모바일은 세로, 넓은 화면은 가로 배치한다.
- 로그인 고객은 `/reservation`, 비로그인 고객은 `/login?next=%2Freservation`으로 이동한다. 일반 로그인·카카오 OAuth·소셜 가입 완료 후 안전한 내부 경로로 복귀한다. 파트너 로그인은 기존 파트너 홈 이동을 유지한다.
- 일반 회원가입 경유도 로그인 → `/signup?next=...` → 가입 완료 `/login?next=...` → 로그인 후 예약 순서로 복귀한다. 가입 화면의 로그인 링크에도 같은 값을 보존한다. 파트너 가입은 기존 `/login` 이동을 유지한다.
- 관리자 미리보기의 두 버튼은 비활성이며 예약 이동·상담 요청·분석 이벤트를 실행하지 않는다.
- 예약 CTA 클릭은 예약 화면 이동만 수행한다. 혜택 배정·결제·예약 확정은 기존 서버/DB 검증 경로에서 처리한다.

## 스테이징 미노출 확인 (2026-10-04)

- 스테이징 프로젝트 `aryrlfprkxntfkpgyayc`의 공개 `opening_event_status` RPC 조회가 HTTP 404 / PGRST202를 반환했다. 이벤트 함수가 없으며 로그인 여부가 원인이 아니다.
- 마이그레이션 목록·dry-run에서 60·63·64·65·66·69 미적용을 확인했다. 원격 적용은 별도 승인 후 수행한다.
- 해당 마이그레이션을 적용해도 기본 `active=false`, `integration_ready=false`이므로 고객 자동 팝업은 표시하지 않는다. 관리자는 `/admin/campaigns/opening`의 `팝업 시안 미리보기`에서 시안을 확인한다.
- 실제 행사 노출·할인 활성화는 #185의 예외 종료·고지·환경 키·운영 검증 완료 후 진행한다. 시안 검토를 위해 이 조건을 우회하지 않는다.
- 활성 행사에서 당일 닫기를 사용한 브라우저는 로컬 날짜가 바뀌기 전까지 다시 노출하지 않는다.

## 승인 후 적용 결과

- 사용자 승인에 따라 스테이징 `aryrlfprkxntfkpgyayc`에 60·63·64·65·66·69를 적용했다. 운영 프로젝트는 변경하지 않았다.
- 적용 후 공개 상태 RPC는 HTTP 200, `enabled=false`, `remaining=20`을 반환한다. 함수 미존재 오류는 해소됐고 고객 자동 팝업은 비활성 조건에 따라 숨겨진다.
- 관리자 시안 미리보기와 실제 이벤트 활성화는 별개다. #185 완료 전 행사 활성화는 하지 않는다.

## 팝업 표시만 활성화 (사용자 결정)

- `OPENING_EVENT_POPUP_PREVIEW=true`는 Vercel Preview이며 Supabase 호스트가 스테이징 `aryrlfprkxntfkpgyayc.supabase.co`일 때만 메인에서 시안 팝업을 자동으로 표시한다. Production 및 운영 Supabase에서는 무시한다.
- 시안은 실제 할인 미적용 안내를 표시하고 예약/상담 버튼은 비활성이다. 미리보기 재검토를 위해 오늘 닫기 저장 상태를 사용하지 않는다. 실제 행사 팝업은 기존 오늘 닫기 및 DB 활성 조건을 그대로 사용한다.
- DB `active`, `integration_ready`는 변경하지 않는다. 고객 자동 시안과 실제 할인 활성화를 분리한다.
- 티켓은 파란 그라데이션·양쪽 반원 홈·하단 점선 절취선으로 첨부 시안의 형태를 구현한다.
- 실제 카카오톡 상담 버튼은 `https://pf.kakao.com/_fImBX`를 새 탭으로 연다. 시안에서는 외부 상담 요청을 실행하지 않는다.
- Preview 환경 변수 변경 후 새 배포가 필요하다. PR #187을 dev에 병합하면 스테이징 dev 배포에 적용된다. 기존 배포에는 환경 변수가 소급되지 않는다.
