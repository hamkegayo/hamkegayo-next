# 첫 1시간 무료 이벤트 (#159)

## 승인된 기준

- 인증된 이메일 계정당 1회. 같은 이메일로 재가입해도 중복 참여를 막는다. 휴대폰 본인인증은 요구하지 않는다.
- 정상 서비스 완료 이력이 없는 고객만 참여한다. 관리자·파트너는 역할로, 직원·테스트 고객은 관리자 제외 목록으로 차단한다.
- Basic 20,000원 / Plus 25,000원 상당의 첫 1시간 기본요금. 최소 예약 2시간이며 할증·추가시간·실비는 별도다. 포인트와 중복 적용하지 않는다.
- 상담 신청이 아닌 결제와 예약 확정 순으로 최대 20건을 배정한다. 회사가 할인액을 부담하고 정상 제공에 대한 파트너 지급액은 유지한다.
- 고객 취소·노쇼는 사용 이력을 유지한다. 노쇼 비용에는 이벤트 할인을 적용하지 않는다.
- 회사·파트너 사유의 제공 불가는 실제 현금 전액 환불이 기록된 뒤 전체/정산 담당자가 증빙과 사유를 확인해 혜택을 복원한다. 기존 순번·시각·복원 담당자를 보존한다. 재예약 시 남은 정원을 다시 확인하며 자리를 미리 보장하지 않는다.
- 고객 요청 조기 종료는 최소 1시간 및 실제 서비스 요금에서 혜택을 차감한다. 회사·파트너 귀책 및 응급 중단은 운영 확인을 거친다.
- 행사 종료 및 관련 취소·환불·결제 사고 처리 완료 후 HMAC과 제외 목록을 파기한다. 거래·접근 이력은 기존 고지에 따른 별도 보관 대상이다.

## 구현

- HTML 팝업은 DB의 active/integration_ready 및 잔여 정원 조건에서만 노출한다. 기존 카카오 채널, 분석 동의 게이트, 당일 닫기를 유지한다.
- 서버 getUser()의 인증 이메일을 HMAC 처리한다. 프로필 입력이나 클라이언트 이메일을 인증 근거로 사용하지 않는다. 이메일 원문은 이벤트 식별 테이블에 저장하지 않는다.
- PG 요청 전에 캠페인 행 잠금과 계정·HMAC 유일 인덱스로 임시 정원을 확보한다. 결제와 예약 확정 트랜잭션에서만 사용을 확정하며 실패·만료는 해제한다.
- 정상 종료는 현금 선결제와 할인 후 최종 청구액을 비교한다. 할인액은 포인트로 환불하지 않는다. 기본 정산과 추가결제·환불 정산을 합산해 이중 계상을 방지한다.
- 전체/정산 담당자와 MFA 인증에 한해 제외 계정 관리, 혜택 복원, 행사 종료를 허용한다. 행사 종료는 되돌릴 수 없으며 진행 중 임시 확보가 있으면 거절한다.
- 마이그레이션 66·69는 기본 active=false, integration_ready=false다. 매일 03:10 KST 파기 작업이 종료·처리 완료 조건을 재검사한다. 종료 후에는 식별 데이터를 재수집하지 않는다.

## 검증

- 이메일 정규화·키 분리·키 길이·할인 후 정상/노쇼 청구액 단위 검사.
- SQL 권한/MFA, 인증 이메일, 제외 계정, 중복·재가입, 포인트 중복, 상품/할증, 만료·실패·재시도, 정원, 확정 롤백 검사.
- 정상 조기 종료의 기본/환불 정산 합계, 노쇼 정산, 전액 환불 전 복원 거절, 복원 감사 이력, 재확보 정원 검사.
- 미처리 예약/결제가 있으면 파기를 보류하고 행사 종료 및 처리 완료 뒤 HMAC·제외 목록을 파기하는 검사.
- 로컬 동시 23건 확보에서 20건 성공/3건 거절 검사. 원격 DB 및 실제 PG 거래는 테스트하지 않는다.

## 활성화 전 확인

아래는 정책 선택이 아니라 배포·운영 준비 확인이다. 완료 전 integration_ready를 변경하지 않는다.

1. 각 환경에 별도의 서버 OPENING_EVENT_EMAIL_HMAC_KEY를 설정한다. 32바이트 이상의 난수를 사용하고 행사 중 교체하지 않는다. 로컬 키는 커밋하지 않는다.
2. 이메일 HMAC 수집 목적·행사 종료 후 파기 기준과 행사 조건을 공개 고지에 반영한다. 노션 정본은 읽기 전용이며 개정 확인이 필요하다. 공고일은 원문에 없으면 임의로 만들지 않는다.
3. 실제 직원·테스트 계정 제외 목록을 등록하고 스테이징 결제·환불·고객 결제 상세를 확인한다.
4. 회사·파트너 귀책 또는 응급 중단을 일반 고객 조기 종료와 구분하는 현장/운영 경로와 수동 정산을 검증한다. 현재 일반 종료 경로만으로 이 예외의 청구 면제가 보장되지는 않으므로 활성화 후 확인으로 미루지 않는다.
5. 스테이징 적용 전 다른 PR의 마이그레이션 이력을 확인하고 66·69를 순서대로 적용한다. 원격 DB 적용, 운영 할인 활성화, main 병합은 이 PR 변경만으로 수행되지 않는다.
