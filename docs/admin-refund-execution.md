# 미달분 환불 승인과 결과 복구

- `/admin/refunds`: 전체/정산 담당자 개인 계정 및 MFA로 접근한다.
- 실제 제공시간, 종료 사유, 고객 환불 금액을 검토한 뒤 사유와 실제 환불 확인을 입력한다.
- PG 원거래 주문·거래번호·금액·잔액을 대조하고, 요청을 DB에서 한 번 선점한 뒤 취소한다.
- 응답이 유실되거나 DB 기록이 실패하면 **결과 조회 및 기록 복구**만 수행한다. 취소를 재호출하지 않는다.
- 원거래 잔액 감소액이 승인 금액과 다르거나 기존 부분 취소가 있으면 PG 콘솔에서 대조한다. 앱 집행 기록이 없는 레거시 APPROVED 건도 재취소하지 않는다.
- 회사·파트너 귀책/응급 종료는 이 흐름으로 집행할 수 없다. 최신 약관에 따른 별도 운영 판단이 필요하다.
- 고객 안내는 DB 환불 기록 완료 후 발송한다. 사고 해결 표시는 고객 안내 확인 후 별도로 기록한다.
- 마이그레이션 79를 프런트 배포보다 먼저 적용해야 한다. 이 PR에서는 원격 DB 적용·실제 취소·이벤트 활성화를 하지 않는다.

기존 PG 직접 호출 함수는 중복 취소를 방지하기 위해 집행을 중단하고 이 관리자 경로로 안내한다. 이 기능은 정상 종료 후 미달분 환불이며 예약 취소의 취소수수료 계산을 바꾸지 않는다.
